# Agent 工程实践资料摘要

## 资料范围

本页汇总用于补充 Agent 工程知识的资料，重点关注 Agent 循环、上下文工程和评估方法。

## Anthropic：Building effective agents

- URL：https://www.anthropic.com/research/building-effective-agents
- 核心启发：
  - 先区分固定编排的 workflow 与由模型动态决策的 agent。
  - 从最简单、可组合的模式开始，仅在收益足够时增加自主性。
  - 常见模式包括 prompt chaining、routing、parallelization、orchestrator-workers 与 evaluator-optimizer。
  - Agent 的关键工程问题不是“会不会调用工具”，而是能否基于环境反馈持续行动并可靠结束。

## Anthropic：Effective context engineering for AI agents

- URL：https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- 核心启发：
  - 上下文窗口是有限预算，不是越多越好。
  - 高质量上下文应同时满足相关、紧凑、可用和可追溯。
  - 长任务需要组合使用检索、压缩、结构化笔记、工具结果清理和子任务隔离。
  - 应优先保存决策、约束、未完成事项和关键证据，而不是完整堆积所有历史。

## OpenAI：A practical guide to building agents

- URL：https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf
- 核心启发：
  - Agent 通常由模型、工具和指令三部分组成。
  - 适合 Agent 的任务往往包含复杂判断、难维护规则或大量非结构化信息。
  - 可靠性依赖明确的工具边界、护栏、人工确认与失败恢复。
  - 多 Agent 会增加协调和评估成本，应在单 Agent 无法清晰处理复杂度时再采用。

## OpenAI：Agent evals

- URL：https://platform.openai.com/docs/guides/agent-evals
- 核心启发：
  - Agent 评估不能只看最终回答，还要检查工具选择、参数、轨迹、状态变化和终止判断。
  - 测试集应覆盖正常路径、工具失败、权限拒绝、上下文污染和长任务。
  - 评估结果应能回放到具体运行轨迹，支持定位是模型、工具、提示词还是环境问题。
