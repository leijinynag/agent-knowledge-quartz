# 手写发布订阅模式

## 题目描述

实现一个简易事件总线 `EventEmitter`，支持：

- `on(eventName, listener)`：订阅事件。
- `off(eventName, listener)`：取消订阅。
- `emit(eventName, ...args)`：发布事件。
- `once(eventName, listener)`：只监听一次。

这是前端手撕中非常高频的一题，也常被用来考察：闭包、Map、数组操作、函数引用、边界情况和设计模式理解。

---

## 30秒回答

发布订阅模式的核心是维护一个“事件名 → 回调列表”的映射。订阅时把回调加入列表，发布时按事件名找到回调列表并依次执行，取消订阅时从列表里删除对应回调。`once` 可以用一个包装函数实现，包装函数执行后先解绑自己，再调用原回调。

---

## 基础实现

```js
class EventEmitter {
  constructor() {
    this.events = new Map()
  }

  on(eventName, listener) {
    if (!this.events.has(eventName)) {
      this.events.set(eventName, [])
    }
    this.events.get(eventName).push(listener)
    return this
  }

  off(eventName, listener) {
    const listeners = this.events.get(eventName)
    if (!listeners) return this

    const nextListeners = listeners.filter(fn => fn !== listener && fn._origin !== listener)

    if (nextListeners.length === 0) {
      this.events.delete(eventName)
    } else {
      this.events.set(eventName, nextListeners)
    }

    return this
  }

  emit(eventName, ...args) {
    const listeners = this.events.get(eventName)
    if (!listeners) return false

    // 复制一份，避免 emit 过程中 off/on 影响当前遍历
    listeners.slice().forEach(listener => {
      listener.apply(this, args)
    })

    return true
  }

  once(eventName, listener) {
    const wrapper = (...args) => {
      this.off(eventName, wrapper)
      listener.apply(this, args)
    }

    // 保存原函数引用，方便 off(eventName, listener) 也能取消 once
    wrapper._origin = listener

    this.on(eventName, wrapper)
    return this
  }
}
```

## 使用示例

```js
const emitter = new EventEmitter()

function handleMessage(msg) {
  console.log('message:', msg)
}

emitter.on('message', handleMessage)
emitter.emit('message', 'hello') // message: hello

emitter.off('message', handleMessage)
emitter.emit('message', 'world') // false

emitter.once('ready', () => console.log('ready'))
emitter.emit('ready') // ready
emitter.emit('ready') // false
```

## 实现要点

### 1. 为什么用 Map？

可以用普通对象，也可以用 `Map`。`Map` 的好处是：

- key 不限于字符串，虽然事件名通常是字符串。
- 不会和对象原型属性冲突。
- API 更适合表示键值集合。

相关：[[30_知识库_Wiki/概念/JavaScript/Map与WeakMap]]

### 2. 为什么 emit 时要 slice？

如果直接遍历原数组，回调执行过程中可能调用 `off` 或 `on` 修改 listeners，导致遍历行为不稳定。

```js
listeners.slice().forEach(fn => fn(...args))
```

复制一份可以保证本轮 emit 使用的是触发瞬间的监听器快照。

### 3. once 如何实现？

`once` 的核心是包装原 listener：

```js
const wrapper = (...args) => {
  this.off(eventName, wrapper)
  listener.apply(this, args)
}
```

如果希望 `off(eventName, listener)` 能取消 once 注册的回调，需要保存原函数引用：

```js
wrapper._origin = listener
```

### 4. 为什么返回 this？

返回 `this` 可以支持链式调用：

```js
emitter.on('a', fn1).on('b', fn2)
```

## 边界情况

- 事件不存在时 `emit` 返回 `false`。
- 同一个 listener 是否允许重复注册？基础版允许；增强版可以去重。
- `off` 一个不存在的 listener 不应该报错。
- `once` 注册后，既可以通过 wrapper 自己删除，也可以通过原 listener 删除。
- emit 过程中 listener 抛错如何处理？基础版直接抛出；增强版可以 try/catch 或异步隔离。
- 是否支持通配符事件，如 `*`？基础面试版一般不需要。

## 增强版：支持清空事件

```js
class EventEmitter {
  constructor() {
    this.events = new Map()
  }

  on(eventName, listener) {
    const listeners = this.events.get(eventName) || []
    listeners.push(listener)
    this.events.set(eventName, listeners)
    return this
  }

  off(eventName, listener) {
    if (!listener) {
      this.events.delete(eventName)
      return this
    }

    const listeners = this.events.get(eventName)
    if (!listeners) return this

    const next = listeners.filter(fn => fn !== listener && fn._origin !== listener)
    next.length ? this.events.set(eventName, next) : this.events.delete(eventName)
    return this
  }

  emit(eventName, ...args) {
    const listeners = this.events.get(eventName)
    if (!listeners || listeners.length === 0) return false

    for (const listener of listeners.slice()) {
      listener.apply(this, args)
    }
    return true
  }

  once(eventName, listener) {
    const wrapper = (...args) => {
      this.off(eventName, wrapper)
      listener.apply(this, args)
    }
    wrapper._origin = listener
    return this.on(eventName, wrapper)
  }

  removeAllListeners(eventName) {
    if (eventName === undefined) {
      this.events.clear()
    } else {
      this.events.delete(eventName)
    }
    return this
  }
}
```

## 发布订阅 vs 观察者模式

| 模式 | 核心关系 | 是否有中间调度中心 | 例子 |
|---|---|---|---|
| 观察者模式 | Subject 直接维护 Observers | 通常没有 | Vue2 Dep / Watcher 思想 |
| 发布订阅模式 | Publisher 和 Subscriber 通过 Event Bus 通信 | 有 | EventEmitter、消息总线 |

面试表达：

> 观察者模式中，被观察对象通常直接持有观察者列表；发布订阅模式中，发布者和订阅者通过事件中心解耦，双方不需要直接知道彼此。

## 复杂度

- `on`：O(1)
- `emit`：O(n)，n 是该事件监听器数量
- `off`：O(n)，需要过滤监听器数组
- 空间复杂度：O(totalListeners)

## 高频追问

### 如何避免重复注册？

可以在 `on` 中判断是否已经存在：

```js
if (!listeners.includes(listener)) listeners.push(listener)
```

### listener 抛错怎么办？

Node.js EventEmitter 会同步触发 listener。如果业务希望一个 listener 报错不影响其他 listener，可以：

```js
for (const listener of listeners.slice()) {
  try {
    listener(...args)
  } catch (err) {
    console.error(err)
  }
}
```

但这会改变错误传播语义，面试时要说明 trade-off。

### 为什么 off once 原函数需要 `_origin`？

因为 `once` 注册进去的实际函数是 wrapper，不是用户传入的 listener。如果用户调用：

```js
emitter.off('ready', listener)
```

就需要通过 `wrapper._origin === listener` 找到并删除 wrapper。

## 面试表达模板

> 我会用一个 Map 维护事件名到回调数组的映射。`on` 负责注册回调，`emit` 找到对应数组并依次执行，`off` 过滤掉要删除的回调。`once` 可以用 wrapper 包一层，执行前先解绑自己。实现时要注意 emit 过程中 listeners 可能被修改，所以最好复制一份再遍历；另外 once 的 wrapper 要保存原函数引用，方便 off 原函数时也能取消。
