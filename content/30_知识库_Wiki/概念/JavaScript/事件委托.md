# 事件委托

## 30秒回答

事件委托是利用事件冒泡，把子元素的事件监听绑定到父元素上统一处理。它可以减少事件监听器数量，并且天然支持动态新增的子元素。常见场景是列表、表格、菜单等大量相似子节点的点击处理。

## 核心代码

```js
const list = document.querySelector('#list')

list.addEventListener('click', (event) => {
  const item = event.target.closest('li')
  if (!item || !list.contains(item)) return
  console.log(item.dataset.id)
})
```

## 核心要点

- 基于事件冒泡。
- 通过 `event.target` 找到真实触发元素。
- 通过 `closest` 和 `contains` 做边界判断。
- 对不会冒泡的事件不适用或需要特殊处理。

## 面试官可能追问

### event.target 和 event.currentTarget 区别？

- `event.target` 是实际触发事件的元素。
- `event.currentTarget` 是当前绑定监听器的元素。

### 哪些事件不适合事件委托？

一些不冒泡的事件不适合直接委托，例如 `blur`、`focus`，可以考虑使用 `focusin`、`focusout` 或捕获阶段。

### 事件委托有什么缺点？

- 需要额外判断目标元素。
- 复杂嵌套结构下可能误判。
- 父级事件过于庞大会降低可维护性。

## 常见错误回答

- 只说“减少绑定事件”，不解释冒泡机制。
- 不区分 `target` 和 `currentTarget`。
- 忽略动态元素场景。
