# 垃圾回收与内存泄漏

## 30秒回答

JavaScript 有自动垃圾回收机制，核心思想是回收不再可达的对象。现代浏览器主要使用标记清除算法，从根对象出发标记可达对象，未标记对象会被回收。常见内存泄漏包括意外全局变量、未清理定时器、闭包长期引用、DOM 引用未释放、事件监听未移除和缓存无限增长。

## 核心要点

- 引用计数无法处理循环引用。
- 标记清除以“可达性”为核心。
- GC 自动进行，但不代表不会内存泄漏。
- 内存泄漏本质是不再需要的对象仍然可达。

## 常见泄漏场景

### 未清理定时器

```js
const timer = setInterval(() => {
  // 持续引用外部变量
}, 1000)

// 组件卸载时应 clearInterval(timer)
```

### 事件监听未移除

```js
window.addEventListener('resize', handler)
// 卸载时 removeEventListener
```

### 闭包长期引用

闭包本身不是泄漏，但如果闭包保存了大对象且长期不释放，就可能造成内存占用。

## 面试官可能追问

### 什么是可达对象？

从 GC Roots 出发可以访问到的对象，例如全局对象、当前调用栈变量、闭包引用等。

### 如何排查内存泄漏？

使用 Chrome DevTools 的 Performance / Memory 面板，观察 heap snapshot、detached DOM、对象数量增长和引用路径。

### WeakMap 为什么有助于内存管理？

WeakMap 的 key 是弱引用，如果 key 对象没有其他强引用，可以被 GC 回收。相关：[[30_知识库_Wiki/概念/深拷贝]]。

## 常见错误回答

- 认为 JS 自动 GC 就不会泄漏。
- 把闭包等同于内存泄漏。
- 不知道 detached DOM 和事件监听的风险。
