# 防抖与节流

## 一句话定义

防抖和节流都是控制高频事件触发频率的函数包装模式：防抖强调“停下来再执行”，节流强调“一段时间最多执行一次”。

## 核心要点

- 防抖 debounce：每次触发都重置定时器，只有最后一次触发后等待指定时间才执行。
- 节流 throttle：在一段时间内只允许执行一次或最多一次。
- 常见场景：输入搜索、窗口 resize、滚动监听、按钮点击保护。

## 原始实现摘要

原始防抖实现使用 `timer` 和 `clearTimeout`；原始节流实现使用 `timer` 标记冷却期，当前版本属于 trailing-timer 风格，不支持 leading/trailing 选项。

## 推荐实现要点

防抖核心：

```js
function debounce(fn, delay) {
  let timer
  return function (...args) {
    clearTimeout(timer)
    timer = setTimeout(() => fn.apply(this, args), delay)
  }
}
```

节流核心：

```js
function throttle(fn, delay) {
  let timer = null
  return function (...args) {
    if (timer) return
    timer = setTimeout(() => {
      fn.apply(this, args)
      timer = null
    }, delay)
  }
}
```

## 边界情况

- 是否首次立即执行，即 leading。
- 是否最后一次补执行，即 trailing。
- 是否需要 `cancel()` 或 `flush()`。
- 箭头函数中的 `this` 是否符合预期。
- 节流也可用时间戳实现，行为与定时器版本不同。

## 面试讲解要点

- 防抖适合“只关心最后一次”的场景。
- 节流适合“持续触发但降低频率”的场景。
- 讲清楚 leading/trailing 会显著提高答案质量。
