# Agent生产故障分类与运行手册

## 一句话定义

Agent 运行手册把常见故障映射到可观察信号、止损动作、定位步骤和恢复策略，使线上问题不必每次依赖临场猜测。

## 故障分类

| 类别 | 典型信号 | 首要动作 |
|---|---|---|
| Provider 故障 | 超时、限流、错误率上升 | 降级、限流、切换 |
| 工具故障 | 某工具失败率上升 | 熔断、禁用或只读降级 |
| Agent 循环 | 轮数和重复调用异常 | 终止、降低预算 |
| 上下文问题 | token 激增、遗漏约束 | 压缩、回滚上下文策略 |
| 质量回退 | 成功率下降 | 回滚模型、prompt 或工具 |
| 权限安全 | 越权、注入、数据泄露 | 立即阻断和审计 |
| 状态一致性 | 重复副作用、任务卡住 | 停止 worker、核对 checkpoint |
| 前端流式 | 事件乱序、无法结束 | 切换轮询、重建状态 |

## 运行手册结构

每类故障至少写清：

- 告警条件。
- 影响范围。
- 立即止损操作。
- 需要查看的 dashboard 和 trace。
- 根因排查顺序。
- 恢复和数据修复步骤。
- 是否需要通知用户。
- 复盘后应加入哪些回归测试。

## 止损优先级

1. 阻止继续扩大副作用。
2. 保护用户数据和凭证。
3. 让新任务进入降级路径。
4. 保存现场 trace 和状态。
5. 再做根因分析和恢复。

对于写工具异常，先禁用写能力或转人工，不要先尝试增加自动重试。

## 发布策略

- prompt、模型和工具版本都可独立回滚。
- 新版本先跑离线评估。
- 小流量或影子模式观察。
- 对成功率、成本、安全和延迟设置发布门槛。
- 保留旧 checkpoint 的兼容读取能力。

## 用户沟通

错误信息要告诉用户：

- 当前发生了什么。
- 已完成部分是否保存。
- 是否产生外部影响。
- 系统会自动恢复还是需要操作。
- 可以重试、继续还是取消。

不要暴露内部堆栈，也不要用“发生未知错误”掩盖可说明的状态。

## 复盘

复盘要区分：

- 模型决策错误。
- prompt 或上下文错误。
- 工具契约错误。
- Runtime 状态错误。
- 权限策略错误。
- 依赖系统故障。
- 监控和测试缺口。

修复后把真实失败轨迹脱敏加入回归集，并验证不会造成新的成本或质量回退。

## 面试表达

我会为 Agent 建立按 Provider、工具、循环、上下文、安全和状态一致性分类的运行手册。事故时先停止副作用并切换降级路径，再通过 trace 和 checkpoint 定位；prompt、模型和工具都能独立回滚，真实失败最终沉淀为回归用例。
