# Workflow与Agent边界

## 一句话定义

Workflow 由代码预先规定执行路径，Agent 让模型根据环境动态决定下一步；二者不是对立方案，可靠系统通常用 Workflow 管阶段，用 Agent 处理局部开放问题。

## 判断维度

| 维度 | Workflow | Agent |
|---|---|---|
| 路径 | 可预先枚举 | 运行时探索 |
| 可预测性 | 高 | 较低 |
| 成本和延迟 | 容易估算 | 波动较大 |
| 测试方式 | 节点输入输出 | 结果与轨迹 |
| 失败恢复 | 代码定义 | Runtime 加模型协同 |
| 适合任务 | 稳定业务流程 | 开放式、多工具任务 |

## 常见 Workflow 模式

- **Prompt chaining**：上一步输出进入下一步，适合固定分解。
- **Routing**：先分类，再进入不同处理链。
- **Parallelization**：并行分析多个独立维度，再聚合。
- **Orchestrator-workers**：中心节点动态拆任务，worker 独立完成。
- **Evaluator-optimizer**：生成后反复评审和修正。

这些模式可以使用模型，但只要路径仍由代码控制，本质上仍是 Workflow。

## 什么时候值得使用 Agent

- 无法提前知道需要调用哪些工具。
- 下一步依赖刚获得的外部结果。
- 任务需要探索、比较和错误恢复。
- 用户目标清楚，但完成路径高度变化。
- 可以定义明确预算、权限和验收器。

不适合的情况：

- 高风险动作无法可靠验证。
- 业务流程有严格事务顺序。
- 输入输出规则稳定且可以编码。
- 单次调用已经能达到质量要求。

## 混合架构

```text
规则校验
  → 确定性路由
  → 受限 Agent 探索
  → 确定性结果验证
  → 人工确认
  → 事务提交
```

模型负责处理语义模糊处，程序负责不可违反的业务约束。

## 设计检查

- Agent 的自主范围是否明确？
- 哪些步骤必须确定性执行？
- 是否有最大轮数和成本预算？
- 最终结果是否可验证？
- 失败后能否降级到 Workflow 或人工？
- 引入 Agent 后的收益是否大于复杂度？

## 面试表达

我不会因为用了多个模型调用就称它为 Agent。判断标准是下一步是否由模型根据环境动态决定。生产系统通常采用混合方式：外层 workflow 固定阶段和风险边界，局部 Agent 负责开放探索，最后回到确定性校验和提交。
