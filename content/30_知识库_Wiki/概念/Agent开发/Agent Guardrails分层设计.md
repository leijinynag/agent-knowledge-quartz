# Agent Guardrails分层设计

## 一句话定义

Agent Guardrails 是部署在输入、上下文、模型输出、工具执行和最终结果各层的约束与检查，用于降低错误和攻击的影响，而不是单一的敏感词过滤器。

## 输入 Guardrail

- 校验文件、URL、大小和内容类型。
- 识别明显越权目标和危险意图。
- 对敏感数据做标记或脱敏。
- 绑定用户、租户和工作区作用域。

## 上下文 Guardrail

- 系统规则与外部内容分区。
- 检索前做权限过滤。
- 限制不可信内容可影响的工具。
- 删除与当前目标无关的 Secret 和个人数据。
- 为证据记录来源和可信等级。

## 输出 Guardrail

- schema 校验。
- 事实引用和证据检查。
- 业务规则、品牌和合规检查。
- 防止敏感信息出现在回复。
- 对低置信度结果转人工或补充检索。

## 工具 Guardrail

- 参数白名单和范围限制。
- 最小权限 capability。
- 沙箱、网络和文件系统限制。
- 副作用预览、审批和幂等。
- 速率、调用次数和成本预算。

## 运行时 Guardrail

- 最大轮数和无进展检测。
- 重复工具调用检测。
- 失败熔断和模型降级。
- 取消传播和执行租约。
- 全量事件审计。

## Guardrail 的局限

- 分类器会有误报和漏报。
- 模型评审也可能被注入影响。
- 规则过严会导致正常任务不可用。
- 安全检查本身会增加延迟和成本。

因此要根据风险分层：高风险动作依赖确定性策略与人工确认，模型类 guardrail 主要作为补充信号。

## 测试方法

- 正常输入不应被大量误伤。
- 直接和间接提示注入。
- 编码、拆分、混合语言绕过。
- 跨租户资源访问。
- 工具参数注入。
- 审批后参数被替换。
- 超时和重试导致重复副作用。

## 面试表达

我会把 guardrail 分布在整个执行链路，而不是只在 prompt 前做内容过滤。高风险控制使用确定性的权限、schema、沙箱和审批，模型分类器只提供辅助判断；同时用攻击集测试绕过率和正常任务误拒率。
