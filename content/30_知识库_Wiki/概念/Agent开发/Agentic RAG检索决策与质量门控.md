# Agentic RAG检索决策与质量门控

## 一句话定义

Agentic RAG 把检索从固定流水线变成 Agent 可以选择、路由、重试和验证的工具流程。

## Pipeline RAG 与 Agentic RAG

### Pipeline RAG

```text
问题 -> 固定检索 -> 拼接上下文 -> 生成答案
```

优点是行为稳定、成本容易估算、适合固定领域问答。缺点是所有问题都检索，无法根据问题类型选择知识源，也难以处理检索结果不足的情况。

### Agentic RAG

```text
问题
  -> 是否需要检索？
  -> 选择知识库/检索器
  -> 执行检索
  -> 判断证据是否充分
  -> 直接回答 / 重写查询 / 切换知识源 / 请求澄清
```

它适合多知识库、复杂问题和需要动态补证据的任务，但会增加模型调用、延迟和失败路径，因此必须设置预算和终止条件。

## 最小可用流程

1. **检索决策**：判断问题是否依赖外部或私有知识。
2. **路由**：根据主题、权限、时效性选择知识库或检索器。
3. **查询改写**：将口语问题转换为更适合检索的查询，但保留原始意图。
4. **证据检查**：检查相关性、覆盖度、冲突和知识源可信度。
5. **生成约束**：要求答案区分证据、推断和未知，不足时明确说明。
6. **受限恢复**：查询重写或 fallback 有次数上限，超过后转人工或请求澄清。

## 质量门控

质量门控不是让模型简单输出一个“相关/不相关”标签，而是检查：

- 证据是否覆盖问题中的关键实体和约束。
- 多个片段之间是否冲突。
- 证据是否过期或超出用户权限。
- 结论是否能回指证据片段。
- 是否需要第二次检索、另一知识库或工具验证。

可以将检索结果标准化为：

```ts
type Evidence = {
  sourceId: string
  title: string
  content: string
  score?: number
  updatedAt?: string
  permissions?: string[]
}
```

## 工程取舍

| 场景 | 建议 |
|---|---|
| FAQ、固定文档问答 | Pipeline RAG |
| 多知识库企业助手 | Agentic RAG + 路由 |
| 需要实时数据 | RAG + API Tool，按时效选择 |
| 高风险回答 | 检索后必须引用、校验或人工审核 |
| 成本敏感且问题简单 | 先分类，尽量跳过不必要检索 |

## 反模式

- 每轮都检索，导致延迟和上下文噪声增加。
- 只看向量相似度，不验证证据是否真的回答了问题。
- 没有重试上限，查询改写陷入循环。
- 把低权限文档检索结果直接暴露给模型或用户。
- 将模型生成的推断伪装成检索事实。
