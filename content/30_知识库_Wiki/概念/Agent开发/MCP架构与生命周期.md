# MCP架构与生命周期

## 一句话定义

MCP 架构由 Host、Client 和 Server 组成，通过初始化、能力协商、发现和调用形成有状态连接，让 AI 应用以统一方式接入外部工具与资源。

## 角色边界

- Host 控制模型、用户授权、上下文和整体安全策略。
- 每个 Client 通常维护与一个 Server 的连接。
- Server 负责实现具体能力，并执行自身的身份和资源检查。

Host 不应因为 Server 声明了某个工具就自动授权模型使用。

## 初始化阶段

连接建立后要交换：

- 协议版本。
- Client 与 Server 信息。
- 双方支持的能力。
- 可选扩展和通知能力。

协商完成前不能假设某个功能可用。连接恢复后也应重新确认能力，而不是永久使用旧缓存。

## 能力发现

Host 可以列出工具、资源和 prompts。为了避免上下文膨胀，发现结果可以保存在本地注册表中，当前任务只加载相关候选的完整定义。

注册表建议保存：

- Server 身份和信任级别。
- 能力名称、描述、schema 和版本。
- 权限范围和风险等级。
- 最近健康状态与延迟。
- 弃用信息。

## 调用与取消

一次调用应带关联 ID，并支持：

- 超时和取消。
- 结构化错误。
- 进度通知。
- 结果分页或外部引用。
- 与 Host trace 的关联。

用户取消时，Host 要同时停止模型循环并向 Server 传播取消；如果 Server 已产生副作用，还要查询最终状态。

## 传输与部署

本地 Server 常通过进程标准输入输出连接，远程 Server 则通过网络传输。两者安全重点不同：

- 本地：进程权限、文件系统、环境变量和命令执行。
- 远程：身份认证、TLS、租户隔离、网络出站和速率限制。

## 版本与兼容

- 工具 schema 变更需要版本策略。
- 删除字段前保留弃用期。
- Host 缓存能力时要支持失效。
- Server 升级后跑契约测试。
- 连接失败要有清晰诊断，不自动改用不受信任 Server。

## 面试表达

我会把 MCP 当成有生命周期的能力连接，而不是静态工具列表。Host 在初始化阶段协商能力，维护本地注册表，并按任务和权限选择候选工具；调用支持取消、超时和 trace，Server 变化通过版本和失效机制处理。
