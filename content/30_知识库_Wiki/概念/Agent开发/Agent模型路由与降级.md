# Agent模型路由与降级

## 一句话定义

模型路由是根据任务难度、能力要求、风险和预算选择模型，降级是在模型不可用、超预算或质量不足时切换到可接受的替代路径。

## 路由信号

- 任务类型：分类、抽取、代码、视觉、复杂推理。
- 上下文长度和输出长度。
- 是否需要 Tool Use 或结构化输出。
- 风险等级与质量要求。
- 当前模型延迟、限流和可用性。
- 用户套餐和任务预算。

路由可以先用规则实现，再用小模型分类，但最终选择应可解释和可记录。

## 常见分层

| 层级 | 任务 |
|---|---|
| 轻量模型 | 分类、改写、简单抽取、查询改写 |
| 主力模型 | 常规生成、工具选择、一般代码任务 |
| 强模型 | 复杂规划、失败恢复、高价值审核 |
| 专用模型 | 向量、语音、视觉、重排序 |

## 降级路径

```text
首选模型
  ├─ 限流 → 同能力备用 Provider
  ├─ 超时 → 更快模型或缩小上下文
  ├─ 预算不足 → 轻量模型 + 固定 Workflow
  ├─ 工具能力缺失 → 切换支持工具的模型
  └─ 质量不达标 → 强模型复核或转人工
```

降级不等于盲目换模型。不同模型的 tool schema、结构化输出和上下文能力可能不同，需要 Provider Adapter 和能力矩阵。

## 质量保护

- 高风险任务不能静默降级到明显更弱的模型。
- 路由变化要写入 trace。
- 每条路由单独评估成功率、成本和延迟。
- 降级后的输出仍需通过同一验收器。
- 避免失败后在多个模型间无限切换。

## 常见失败模式

- 只按价格选择模型。
- 所有重试都切换 Provider，导致行为难以复现。
- 模型能力矩阵长期不更新。
- 降级模型不支持原工具或 schema。
- 高价值任务降级后没有提示或人工复核。

## 面试表达

我会用任务能力、上下文、风险、实时可用性和预算做模型路由，并为每条路径保留明确的降级策略。路由与切换都会进入 trace，最终仍使用统一验收器，避免“请求成功”被误当成“任务成功”。
