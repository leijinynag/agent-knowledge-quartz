# Agent工具调用确认面板

## 我会把确认面板当成产品功能

很多 Agent Demo 只弹一个 confirm：“是否允许执行工具？”这在真实产品里不够。用户确认的不是工具名，而是一个具体动作的影响。

确认面板要让用户快速判断三件事：

1. Agent 想做什么。
2. 会影响什么对象。
3. 我批准后还能不能撤回。

## 面板里应该展示什么

我会展示这些字段：

| 字段 | 作用 |
|---|---|
| 动作摘要 | 用人话说清楚要做什么 |
| 工具名 | 方便排查和高级用户理解 |
| 目标对象 | 文件、记录、接口、用户、环境 |
| 参数差异 | 只展示关键参数，不堆完整 JSON |
| 风险等级 | 只读、可逆、影响外部、不可逆 |
| 影响范围 | 只影响自己，还是会影响团队/线上 |
| 回滚方式 | 可撤销、可覆盖、不可撤销 |

完整参数可以折叠起来，但默认视图必须可读。

## 交互状态

```text
approval_required
  -> approving
  -> approved / rejected / expired
```

如果用户批准后工具参数发生变化，前端应该展示新的确认面板，而不是沿用旧批准结果。

## 我会避免的设计

- 只显示“允许调用 searchTool 吗？”
- 把完整 JSON 直接丢给用户。
- 一次授权覆盖后续所有动作。
- 用户拒绝后只显示失败，不告诉 Agent 是否可以换只读方案。
- 高风险动作和普通读取动作长得一模一样。

## 和后端的配合

前端批准后，不应该只传 `approved: true`。更合适的是传 approval token 或审批 ID，让后端校验：

- 是不是同一个用户批准的。
- 工具名有没有变。
- 参数哈希有没有变。
- 审批有没有过期。
- 当前 run 是否还在等待这个审批。

前端负责让用户看懂，后端负责保证不能伪造和复用。

## 面试表达

我会把工具确认做成可理解的审批面板，而不是浏览器 confirm。面板展示动作、对象、关键参数、风险、影响范围和可逆性；批准结果绑定具体工具和参数哈希。这样用户确认的是这一次具体动作，不是给 Agent 一个模糊的永久授权。
