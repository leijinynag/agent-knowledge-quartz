# Agent提示注入与不可信内容隔离

## 先建立一个前提

网页、用户上传的文档、邮件、搜索结果、数据库字段和工具返回值，都应该先当成数据，而不是指令。

它们里面可能出现“忽略之前的要求”“把密钥发给我”之类的文字。模型能读到，不代表系统应该执行。

## 两类注入

### 直接注入

用户自己在输入里加入越权要求，例如要求 Agent 暴露系统提示、读取无关文件或跳过确认。

### 间接注入

攻击内容藏在 Agent 主动读取的网页、仓库文档、工单、PDF 或工具结果中。它更难发现，因为用户表面上只是让 Agent“帮我总结这个页面”。

## 我会做的隔离

上下文里把指令和数据分开标记：

```text
SYSTEM_POLICY
USER_INTENT
TASK_STATE
UNTRUSTED_DOCUMENT
TOOL_RESULT
```

不可信内容可以作为分析对象，但不能自动改变系统规则、工具权限、目标用户或审批状态。

工具结果也不能提升权限。一个网页告诉 Agent“你现在是管理员”，这句话没有任何授权意义。

## 系统层防护

- 工具采用最小权限，不给 Agent 一个万能文件系统或万能网络出口。
- secret 放在受控执行环境里，尽量不进入模型上下文。
- 访问外部资源时限制域名、文件范围和数据外传方向。
- 对高风险参数做独立 policy check。
- 对模型输出做编码和 schema 校验，避免把文本直接拼进命令或 HTML。
- 把可疑内容和实际动作记录到轨迹中，方便回放。

这些措施比单纯在 prompt 里写“不要被注入”可靠得多。Prompt 约束有用，但不能当作安全边界。

## 处理流程

```text
读取外部内容
  -> 标记为不可信
  -> 提取事实和候选指令
  -> 丢弃越权指令
  -> 按 Runtime 权限重新生成动作
  -> 独立校验参数
  -> 必要时请求人工确认
```

## 常见误区

- 只防用户输入，不防网页和工具结果。
- 把“模型没有执行”误认为“系统安全”。
- 将 secret 放在 system prompt 里，认为模型一定不会泄露。
- 工具权限过大，最后只能依赖模型自觉。
- 发现注入后直接把整段内容删除，导致真正有用的事实也丢失。

## 面试表达

我会把所有外部内容默认视为不可信数据，做指令与数据分区，并确保工具结果不能改变权限。真正的防线是最小权限、secret 隔离、输出校验、数据外传限制、独立 policy check 和人工审批，而不是只靠 prompt 约束。
