# Agent基准测试与离线评估

## 一句话定义

Agent 离线评估是在可重复环境中运行一组带验收条件的任务，对成功率、轨迹、成本和安全行为进行对比，用于发布前发现回退。

## 样本结构

```json
{
  "case_id": "repo-fix-001",
  "input": {"goal": "修复指定测试"},
  "environment": {"fixture": "repo-v3"},
  "criteria": {
    "tests_pass": true,
    "allowed_paths": ["src/", "test/"],
    "forbidden_tools": ["publish"]
  },
  "budget": {
    "max_turns": 12,
    "max_cost": 0.5
  }
}
```

样本必须固定环境或记录数据版本，否则结果无法比较。

## 验收器

- 单元测试和端到端测试。
- schema、正则和字段约束。
- 数据库最终状态。
- 文件差异和路径白名单。
- 必须或禁止出现的工具事件。
- 模型评审 rubric。
- 人工评分。

确定性验收器优先。模型评审适合开放文本，不适合判断权限是否违规。

## 指标

- Task success rate。
- 首次成功率。
- 恢复后成功率。
- 工具选择和参数准确率。
- 约束违反率。
- 平均与 P95 延迟。
- 每个成功任务成本。
- 多余步骤率。

指标必须一起看。更高成功率如果伴随十倍成本，不一定适合上线。

## 对比实验

修改 prompt、模型、工具或 Runtime 后：

1. 固定评估集和环境。
2. 多次运行处理模型随机性。
3. 与当前生产基线比较。
4. 查看整体指标和具体失败样本。
5. 对高风险回退设置发布阻断。

## 数据集维护

- 高频业务样本保持稳定。
- 新能力加入对应测试。
- 线上失败脱敏后进入回归集。
- 定期移除过期或泄漏的样本。
- 防止评估样本被直接写入 prompt。
- 按任务、难度和风险做分层统计。

## 常见失败模式

- 只跑一次就下结论。
- 只比较最终文本相似度。
- 评估数据已经出现在训练或 prompt 中。
- 工具环境不固定。
- 用平均分掩盖高风险任务回退。
- 只优化 benchmark，忽略真实线上分布。

## 面试表达

我会把每个评估样本定义为输入、固定环境、验收器和预算。发布前对比成功率、轨迹、成本和安全指标，开放文本才使用模型评审。线上失败会变成新的回归用例，但不会让测试集完全替代线上监控。
