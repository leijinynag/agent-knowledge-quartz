# Prompt Caching与上下文缓存

## 一句话定义

Prompt Caching 复用请求中稳定且重复的上下文前缀，以降低延迟和输入成本；它优化的是重复计算，不替代上下文裁剪、检索和记忆管理。

## 适合缓存的内容

- 稳定系统规则。
- 大而固定的参考文档。
- 变化较少的工具定义。
- 同一长会话反复使用的历史前缀。
- 固定代码库说明或领域规范。

不适合缓存：

- 每次都变化的用户输入。
- 高频更新的任务状态。
- 含短期敏感信息的上下文。
- 顺序不稳定的工具列表。

## 上下文布局

```text
稳定规则
→ 稳定工具和参考资料
→ 较稳定会话摘要
→ 当前任务状态
→ 当前用户输入
```

频繁改变前缀中的一个字符都可能降低复用，因此工具顺序、序列化方式和空白格式也要稳定。

## 监控指标

- 缓存命中率。
- 缓存读取与写入 token。
- 命中和未命中的延迟差异。
- 每个成功任务的实际节省。
- 前缀版本变化频率。

高命中率不一定代表高收益。如果前缀本身没有必要，最好的优化仍是删除它。

## 与其他缓存的区别

- Prompt cache：复用模型输入前缀。
- Semantic cache：相似问题直接复用结果。
- Retrieval cache：复用检索结果。
- Tool result cache：复用外部工具返回。

结果类缓存必须考虑权限、时效和数据版本，不能跨租户误用。

## 常见失败模式

- 为追求命中把过多无关内容固定在前缀。
- 规则更新后仍命中旧语义。
- 工具列表顺序随机导致缓存失效。
- 缓存键没有租户和权限作用域。
- 只看输入 token 降低，没有评估回答质量。

## 面试表达

我会把稳定前缀和动态状态分开，并监控缓存命中、延迟和真实成本。Prompt caching 只是性能优化，不能成为保留无关上下文的理由；涉及检索和工具结果的缓存还要带权限、版本和过期策略。
