# Agent上下文工程

## 一句话定义

Agent 上下文工程是围绕任务目标主动选择、组织、压缩和更新模型可见信息的工程过程，目标是在有限上下文预算内提供完成当前决策所需的最小充分信息。

## 核心要点

- 上下文不是数据库快照，而是给“当前这一步决策”准备的工作集。
- 信息越多不一定越好；噪声、冲突和过期内容会降低决策质量。
- Memory 负责保存，Retrieval 负责寻找，Context Engineering 负责决定本轮给模型看什么。
- 长任务需要让重要状态外部化，避免只依赖对话历史。
- 压缩必须保留约束、决策依据、未完成事项和证据位置。

## 上下文分层

| 层级 | 典型内容 | 更新频率 |
|---|---|---|
| 稳定指令 | 角色、规则、权限、输出契约 | 低 |
| 任务状态 | 目标、验收条件、计划、进度 | 中 |
| 工作记忆 | 当前步骤需要的文件片段、工具结果 | 高 |
| 情节记忆 | 过去运行、用户偏好、历史决策 | 按需检索 |
| 外部知识 | 文档、代码库、数据库、网页 | 按需检索 |

## 最小充分上下文

构建每轮上下文时可以按以下问题筛选：

1. 当前要做的决策是什么？
2. 哪些约束会改变这个决策？
3. 哪些事实可以直接支持行动？
4. 哪些历史只需保留摘要或引用？
5. 哪些内容已经过期、重复或可以重新检索？

一个实用的上下文包可以包含：

```text
稳定指令
+ 当前目标与验收条件
+ 当前计划和未完成步骤
+ 最近关键事件
+ 本轮所需证据
+ 可调用工具及权限
+ 输出格式
```

## 常见策略

### 选择

- 只检索与当前子目标相关的文档片段。
- 使用文件路径、标题、时间、标签和权限做过滤。
- 对工具只暴露当前阶段可用的最小集合。

### 压缩

- 把长对话压缩成决策、证据、风险和待办。
- 将大型工具结果保存到外部文件，只在上下文中放摘要与引用。
- 合并重复观察，删除已被后续事实覆盖的状态。

### 隔离

- 为子任务创建独立上下文，返回结构化结果而不是完整过程。
- 将不可信外部内容与系统指令分区，防止指令混淆。
- 多 Agent 协作时通过明确交接契约传递必要状态。

### 外部化

- 使用 scratchpad、任务清单、事件日志或状态对象保存进度。
- 对关键事实保留证据位置，允许后续重新读取和验证。
- 对长期记忆设置写入条件、生命周期和冲突处理规则。

## 上下文压缩的风险

- 丢失否定条件，例如“不要修改生产数据”。
- 把假设压缩成事实。
- 丢失证据位置，导致无法验证。
- 忘记未完成的子任务。
- 保留旧状态，覆盖更新后的真实环境。

因此压缩结果应至少包含：

- 当前目标与成功标准。
- 不可违反的约束。
- 已做决策及理由。
- 已完成和未完成事项。
- 关键证据及其位置。
- 风险、错误和恢复状态。

## Memory、RAG 与上下文工程

| 概念 | 核心问题 |
|---|---|
| Memory | 什么值得跨轮次保存？ |
| RAG / Retrieval | 从外部知识中找回什么？ |
| Context Engineering | 当前决策应该让模型看到什么？ |

三者不是替代关系。可靠 Agent 通常需要外部保存状态，按任务检索，再将检索结果压缩成当前步骤的上下文。

## 面试表达

我不会把全部历史持续塞进 prompt，而是维护一个外部任务状态，并按当前子目标构造最小充分上下文。长工具结果存引用，历史对话压缩为决策和待办，不可信内容与指令隔离，同时保留证据位置以便重新验证。
