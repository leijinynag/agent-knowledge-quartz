# Agent记忆与上下文管理

## 一句话定义

上下文管理决定当前这一步给模型看什么，记忆系统决定哪些信息值得跨步骤或跨会话保存；两者共同目标是在有限预算内保留完成任务真正需要的信息。

## 五种容易混淆的数据

| 类型 | 作用 | 典型生命周期 |
|---|---|---|
| 对话历史 | 保持当前交流连贯 | 当前会话 |
| 工作状态 | 计划、待办、变量、证据 | 当前任务 |
| 长期记忆 | 用户偏好、稳定事实、历史经验 | 跨会话 |
| 外部知识 | 文档、代码、数据库 | 外部系统长期保存 |
| 缓存 | 复用重复计算或稳定 prompt | 按缓存策略 |

对话历史不等于记忆，向量库也不等于完整记忆系统。

## 当前上下文怎么组装

推荐按优先级构造：

```text
稳定规则
+ 当前目标与成功标准
+ 当前任务状态
+ 最近关键交互
+ 本步骤所需证据
+ 当前可用工具
+ 输出契约
```

每轮都问：

1. 当前要做的决策是什么？
2. 哪些约束会改变这个决策？
3. 哪些事实可以支持行动？
4. 哪些内容可通过引用重新读取？
5. 哪些历史已经过期或重复？

详见：[[30_知识库_Wiki/概念/Agent开发/Agent上下文工程]]

## 上下文压缩

压缩不是随手做摘要。至少要保留：

- 用户目标和验收条件。
- 不可违反的约束。
- 已完成与未完成步骤。
- 已做决策及理由。
- 关键证据的位置和置信度。
- 工具副作用与确认记录。
- 已发生错误和恢复状态。

长工具结果应保存在外部对象、文件或 trace 中，上下文只放摘要和引用。需要细节时再精确读取。

## 长期记忆写入

不是每句话都值得保存。可设置写入门槛：

- 未来任务可能重复使用。
- 内容相对稳定。
- 用户明确表达了偏好或长期事实。
- 信息来源和置信度可记录。
- 不包含不必要的敏感数据。

写入前做去重和冲突检测，读取时考虑时间、来源、作用域和置信度，过期信息要衰减或删除。

详见：[[30_知识库_Wiki/概念/Agent开发/Agent长期记忆写入与遗忘策略]]

## Memory 与 RAG

| 问题 | Memory | RAG |
|---|---|---|
| 主要保存什么 | 用户和任务历史 | 外部知识 |
| 写入方式 | 运行中选择性写入 | 预先索引或持续同步 |
| 检索信号 | 用户、任务、时间、语义 | 查询、元数据、权限 |
| 主要风险 | 错误记忆、隐私、过期 | 召回错误、证据不足 |

Agentic RAG 会由模型决定何时检索、如何改写查询、是否继续检索，但检索质量门控和权限过滤仍应由程序控制。

详见：[[30_知识库_Wiki/概念/Agent开发/Agentic RAG检索决策与质量门控]]

## Prompt Caching

缓存适合稳定、重复、较大的前缀，例如系统规则、工具说明和固定参考资料。为了提高复用：

- 把稳定内容放前面。
- 把用户输入和动态状态放后面。
- 监控命中率、缓存读写 token 和实际节省。
- 规则变化后确保缓存键或前缀发生变化。

详见：[[30_知识库_Wiki/概念/Agent开发/Prompt Caching与上下文缓存]]

## 多 Agent 的上下文隔离

子 Agent 不应默认继承主 Agent 的完整历史。更好的交接包是：

```json
{
  "objective": "需要完成的子目标",
  "constraints": ["不可违反的限制"],
  "inputs": ["必要证据或引用"],
  "expected_output": "结构化返回格式",
  "budget": {"turns": 6}
}
```

子 Agent 返回结论、证据、风险和未解决问题，不返回全部内部过程。

## 常见失败模式

- 无限追加历史，导致成本增长和注意力稀释。
- 压缩时丢失“不要做什么”。
- 把模型推测写成长期事实。
- 检索内容没有权限过滤。
- 使用过期记忆覆盖当前真实状态。
- 工具结果被截断后，模型不知道数据不完整。
- 多 Agent 互相转发完整上下文，产生指数级膨胀。

## 面试表达

我会把会话、任务状态、长期记忆和外部知识分开保存。每轮根据当前子目标构造最小充分上下文，长结果只放摘要和引用；长期记忆有写入门槛、来源、置信度和过期策略。这样上下文不会随着运行时间无边界增长，也能减少错误记忆污染。
